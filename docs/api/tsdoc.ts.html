tsdoc.ts

TSDoc/JSDoc parsing helpers using the TypeScript compiler API.

Provides parseComment for extracting JSDoc/TSDoc from TypeScript nodes. Primarily designed for build-time code generation but can be used at runtime.

Design

Pure extraction approach: extracts documentation as-is with minimal transformation, preserving source intent. Works around TypeScript compiler API quirks where needed.

Supports both regular TypeScript and Svelte components (via svelte2tsx output).

Tag support

Supports the common JSDoc/TSDoc doc tags as used across the TypeScript ecosystem: @param, @returns, @throws, @example, @deprecated, @internal, @see, @since, @default, @nodocs. Where the two standards spell a tag differently, both spellings are accepted: @return (JSDoc synonym) parses like @returns, and @defaultValue (the TSDoc spelling, plus JSDoc's lowercase @defaultvalue synonym) parses like @default.

@internal is a marker, not an exclusion: it means "not stable public API" and lands as internalMessage (with any trailing prose; empty string for a bare tag) while the declaration stays documented. @nodocs excludes a declaration from documentation and flat-namespace validation — it's still exported and usable, just not documented.

Also supports @mutates (non-standard) for documenting mutations to parameters or external state. Format: @mutates target - description of mutation — the target is everything before the first - separator. It is unvalidated: typically a parameter name, but compound paths (this.foo, obj.field) and multi-word external references are accepted; backticks are stripped from the target so `` a `` and a are one key. Without a separator the first line is a bare target (empty description) and any continuation lines are the description.

Also supports @cssprop (the Custom Elements Manifest convention; @cssproperty is a synonym) for documenting a Svelte component's CSS custom properties: @cssprop {<syntax>} [--name=default] - description, where the braced syntax, the brackets, and the default are optional (parseCsspropTagText). It documents only a component, in its doc comment; elsewhere it warns misplaced_tag. A tag whose text names no custom property, and a tag repeating an earlier tag's name, are kept apart in cssPropertyProblems for the analyzers to warn about (malformed_tag, duplicate_tag); they still count as doc content, so a comment of broken tags alone claims the doc slot and gets its warnings.

The @see tag supports multiple formats: plain URLs (https://...), {@link} syntax, and module names. Relative/absolute path support in @see is TBD.

Behavioral notes

@module blocks are excluded from parseComment (see there). Module comments go through the same parser by text: parseModuleComment rewraps a module comment, from TS or either Svelte form, as a JSDoc block without its @module line, and toModuleDocFields keeps the tags a module can carry.

JSDocPropertyLikeTag nodes (@property/@param declaring a symbol in a typedef or callback) parse to their own tag description — the only doc such a declaration can carry.

@typedef/@callback tags declare type aliases in JS. A block declaring one without a @param or @returns is a typedef block (isTypedefBlock). As in TypeScript's hover, the declaration it's attached to skips it. Its typedef takes the block's prose and tags (hover shows no block tags on a typedef) unless the block declares several (typedefOwnsBlock), and a function doc block stays the function's, leaving a typedef in it only its own tag comment; both are stricter than hover, which gives every typedef the block's prose. A @callback's JSDocSignature parses to its @param/@returns text. Comment text parsed without a node (parseCommentText) and the in-script component JSDoc keep a typedef block's prose (skipTypedefBlocks: false).

Due to TS Compiler API limitations:

  • TS API includes dash separator in @param tag text; we strip the leading - as it's syntax, not content
  • @throws braced types ({TypeError}) parse into the tag's typeExpression, not its text — the type is read from there; unbraced text falls back to a first-word-as-type regex, the single word bare or in backticks (recorded without them)
  • TS API strips URL protocols from @see tag text; we use getText() to preserve original format including {@link} syntax

Whether a parsed comment carries any documentation — description text or an extracted tag.

Type machinery parses to an empty result (@type/@typedef/@template tags populate no fields), so doc-hunting walks (component docComment) use this to keep lower-precedence sources like the HTML @component comment reachable instead of letting an annotation claim the doc slot with empty text. jsdocParamTagDefault(tag: JSDocParameterTag, sourceFile?: SourceFile): string | undefined

The default a bracketed @param tag writes (@param {number} [b=0] → 0), verbatim source text with quotes kept, matching an initializer's defaultValue. TypeScript's JSDoc parser reads the = … expression and discards it, so the text is sliced from the source: from the = after the name to the bracket that closes the name, skipping brackets and quoted strings inside the default ([b=[1, 2]], [b='a]']). A multi-line default drops each continuation line's * margin. A regex literal containing ] isn't recognized ([c=/]/] reads as /). Callers use it only for an omittable parameter: a bracket on a non-omittable one (a TS b: number with no ?) is ignored.

parseComment(node: Node, sourceFile?: SourceFile, skipTypedefBlocks?: boolean): TsdocParsedComment | undefined

Parse JSDoc comment from a TypeScript node.

Extracts and parses all JSDoc tags including:

  • @param - parameter descriptions
  • @returns - return value description (@return accepted as a synonym)
  • @throws - error documentation
  • @example - code examples
  • @deprecated - deprecation warnings
  • @internal - internal-API marker (trailing prose kept)
  • @see - related references
  • @since - version information
  • @default - default value (@defaultValue/@defaultvalue accepted as synonyms)
  • @mutates - mutation documentation (non-standard)
  • @nodocs - exclusion flag (non-standard)
  • @cssprop - a component's CSS custom property (@cssproperty accepted as a synonym); a tag that documents nothing lands in cssPropertyProblems

A JSDoc @typedef or @callback tag parses to the typedef's docs (parseTypedefComment), and a @callback's signature to its parameter and return descriptions (parseCallbackSignatureComment).

A JS function, method, or constructor with @overload tags is documented by its overloads, as the checker types it: an @overload's signature parses to its block's docs plus its own @param and @returns tags (parseOverloadSignatureComment), and the declaration to its first overload's (firstJSDocOverloadSignature). The implementation's own block is hidden, prose and tags alike, as a TypeScript implementation signature's JSDoc is.

JSDoc blocks tagged @module are excluded entirely (text and tags): a module comment attaches to the file's first statement in the AST, and without the filter it would read as that statement's own docs. Module comments parse through parseModuleComment, which parses the comment's text the same way. Typedef blocks (isTypedefBlock: a @typedef/@callback without a @param or @returns) are excluded the same way, as TypeScript's hover skips them: they document their typedefs, not the declaration below. skipTypedefBlocks: false keeps them, for a block that stands for a module or component comment, which a @typedef line doesn't make a typedef's: there the tag drops as an unknown one, and the prose stays.

import {parseComment} from 'svelte-docinfo/tsdoc.ts';

parameters

node
: Node
#

the TypeScript node to extract JSDoc from

sourceFile
?: SourceFile = node.getSourceFile()
#

source file for full-text tag reads (@see); defaults to the node's own

skipTypedefBlocks
?: boolean = true
#

whether typedef blocks are excluded

returns

parsed comment with structured metadata, or undefined if no JSDoc found (or only @module and typedef blocks)

examples

const tsdoc = parseComment(declarationNode, sourceFile); if (tsdoc) { console.log(tsdoc.text); // main comment text console.log(tsdoc.params); // {paramName: 'description'} }

parseCommentText(text: string): TsdocParsedComment | undefined

Parse comment text that has no node of its own with parseComment, so it reads every tag exactly as a declaration's JSDoc does.

The text is rewrapped as a JSDoc block on a throwaway statement and parsed there. A *\/ in it (an HTML comment can hold one) is escaped for the parse with a placeholder the text doesn't hold, and restored in the result, and so is an @ in the middle of a line: only a line-leading @ starts a tag here, where a declaration's JSDoc, read by TypeScript in place, starts one at any @ after whitespace. A @module line makes the block a module block, which parseComment skips, so parseModuleComment strips it first.

text

returns

the parsed comment; its text is empty when the comment holds only tags
